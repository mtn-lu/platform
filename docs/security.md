# Security boundaries

**Every backend under mtn.lu is trusted with the shared credential.** A compromised games.mtn.lu server receives the Domain=mtn.lu cookie. HttpOnly protects against browser JavaScript reading the cookie; it does not isolate sibling backends. Never host untrusted HTML, third-party apps, or untrusted preview code anywhere below mtn.lu. Separate D1 databases reduce data coupling, not credential exposure. Future isolation could use host-only per-app sessions and standards-based SSO; this is not an OAuth/OIDC provider.

Only the root application accepts browser authentication mutations. Exact configured Origin is mandatory, including for logout; missing/null/sibling Origin fails closed. Fetch Metadata, when present, must indicate same-origin and not a navigation or no-cors request. JSON is mandatory and bodies are streamed with a 2 KiB cap. No cross-origin credentialed CORS exists. Return origins have a separate explicit list; URL parsing checks exact origins, rejects credentials, fragments, encoded characters, backslashes, controls and protocol-relative paths. This conservative policy deliberately disallows encoded return URLs rather than trying to canonicalize dangerous multi-encoded inputs.

The only public auth endpoints are request-link, confirm, logout and logout-all. GET/HEAD never redeem tokens. Better Auth's native handler is not mounted. The facade calls documented server APIs and forwards only Set-Cookie, never raw library JSON or redirects. The confirmation credential belongs in the fragment, is removed into component memory, and is redeemed only on Continue. Refresh after removal requires reopening the email. Email may open on another device; there is no same-browser prerequisite. Confirmation reduces accidental scanner activation, not phishing risk. Anyone possessing an unused link can sign in.

Magic-link tokens: Better Auth's supported hashed storage, 15 minutes, atomic delete-and-return consumption on D1. Sessions: random tokens in the library's database format, signed HttpOnly cookies, **not hashed session storage**. Fixed 30-day expiry, no rolling refresh or cookie data cache. Deferred refresh plus disableRefresh keeps RPC validation read-only even for expired sessions. Reauthenticate after expiry. Library session creation and consumption remain authoritative; platform allowlist hooks and SQL insertion triggers add deny-by-default membership policy. Reads always recheck membership. Revocation retains stable user IDs. A request already authorized before concurrent revocation may finish; subsequent requests fail.

Production cookies use __Secure-mtn.session_token; Domain=mtn.lu, Path=/, Secure, HttpOnly, SameSite=Lax. Localhost uses a separate host-only name and independent secret. HTTPS subdomain tests use mtn.test and a separate database/secret. Logout revokes before clearing library cookies with matching scope. Shared credentials must never appear in browser JSON, logs, render output, or app return URLs.

Abuse counters use atomic D1 upserts and keyed HMAC identifiers. Defaults: 3 requests/address and 20/IP per fixed 15-minute window, 30 confirmations/IP/window, 50 outbound attempts/day. Fixed windows can permit bursts at boundaries. Counters saturate at the limit; concurrent instances cannot exceed a bucket. Membership does not change public rate-limit rules or status/body. A neutral acknowledgement is not evidence of email delivery; delivery timing is not guaranteed indistinguishable. Production IP input is Cloudflare's overwritten CF-Connecting-IP; all loopback clients share one local bucket. Never use a caller-provided proxy header outside the actual Cloudflare ingress.

The hourly maintenance handler deletes at most 500 expired rows per table per invocation. Auth timestamps are ISO strings in the installed native D1 adapter. It never migrates a database. Monitor backlog if limits or audience grow; run the documented bounded cleanup repeatedly when recovering a backlog. Local email capture has a separate local-only table and expires after 15 minutes; no public inbox route exists. Production rejects capture and requires a configured email binding.

Application logs contain event/code, generated correlation ID and duration, not input payloads, provider exceptions or URLs. Better Auth logger payloads are discarded. Wrangler observability is off, including invocation logs, to avoid automatic URL capture. Review Cloudflare account-level Logpush, traces and any later observability changes before enabling them. Static and Worker security headers are configured separately. No HSTS namespace preload or includeSubDomains is asserted.
